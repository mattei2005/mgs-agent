# Aprendizado Contínuo — Referências, Libraries e Variações

Use esta referência para manter o Ares evoluindo conforme Rodolfo, Geizian, Kelly e gestores enviam novas referências, libraries, prints, anúncios, vídeos e correções.

## Regra central

Toda correção criativa recorrente ou padrão aprovado/reprovado deve virar aprendizado da skill. O Ares deve aprender com a operação, não repetir erro em novas threads.

## Quando atualizar a skill

Atualize ou proponha atualizar quando acontecer qualquer item abaixo:

```text
Sinal                                      Ação
─────────────────────────────────────────  ─────────────────────────────────────────────
Rodolfo corrige padrão criativo             Patch imediato na referência apropriada.
Gestor aprova um prompt/estrutura           Registrar como exemplo positivo.
Gestor reprova por motivo claro             Registrar anti-padrão.
Nova vertical ou subvertical aparece        Criar/estender referência vertical.
Library/referência mostra padrão útil       Resumir linguagem visual e arquétipo.
Erro técnico recorrente                     Registrar pitfall e validação.
```

## Como registrar aprendizado

Use blocos curtos, não logs enormes.

```text
## Aprendizado — [data curta / tema]
Origem: [Rodolfo/Geizian/Kelly/gestor/ref]
Contexto: [pedido]
Decisão: [o que foi aprovado/reprovado]
Aplicar em: [CAR/CC/GAME/video/image/provider]
Prompt melhorado: [trecho curto]
Anti-padrão evitado: [se houver]
```

## Biblioteca de referências

Quando receber várias referências/libraries:

1. analisar cada referência com evidência mínima;
2. agrupar por arquétipo, não por arquivo solto;
3. extrair linguagem visual comum;
4. sugerir variações criativas novas;
5. registrar padrões úteis na vertical/formato.

```text
Exemplo de agrupamento
──────────────────────
CAR / Vendedor direto / showroom / oferta sem entrada
CAR / POV test-drive / desejo / parcela baixa
CC / App wallet / aprovação / CTA Apply Now
GAME / Gameplay hook / reward reveal / creator reaction
```

## Prompt antes de gerar quando vago

Quando o pedido estiver vago ou puder seguir caminhos muito diferentes, o Ares deve primeiro mostrar o que entendeu e o prompt que pretende usar. O prompt precisa ser copy-paste/editável pelo gestor.

Objetivo: permitir que Geizian/Kelly/gestores ajustem antes da geração, reduzindo retrabalho e ensinando o Ares com as alterações.

## Checklist aprendizado

- [ ] A correção virou regra reutilizável?
- [ ] O aprendizado está no arquivo certo: vertical, formato ou provider?
- [ ] Foi registrado como padrão prático, não como histórico temporário?
- [ ] O prompt melhorado está claro e editável?
- [ ] A resposta final informou que a skill foi atualizada?
