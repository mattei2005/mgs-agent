# Drive final organization: RAW preservation, review cleanup, and ready promotion

Use this reference when Rodolfo asks to finish/resolve Drive creative organization after UPLOAD_CANVAS assets have been copied into operation folders.

## Mental model to explain clearly

```text
UPLOAD_CANVAS bruto      -> cópia limpa/sanitizada -> pasta vertical final
Arquivo original RAW        arquivo derivado          arquivo pronto para uso
```

- `UPLOAD_CANVAS` is the original/source layer. Preserve it unless Rodolfo explicitly asks to delete RAW.
- Operation folders (`CC_US_EN/...`, `CC_US_ES/...`, etc.) contain cleaned/sanitized derivatives with final names.
- `REVIEW` / `00_REVIEW` is a temporary staging layer for cleaned copies that need visual decision.
- A RAW file and its cleaned derivative usually will NOT share MD5 because metadata cleaning changes the binary. Do not conclude they are unrelated just because MD5 differs.

## Required final-state checks

After promotion/cleanup, generate a fresh Drive inventory and verify:

```text
Check                                      | Expected
-------------------------------------------|-------------------------------
UPLOAD_CANVAS                              | preserved unless explicitly deleted
REVIEW / 00_REVIEW                         | 0 files after final review
01_READY_CANDIDATE                         | 0 files after promotion
01_READY                                   | all approved organized assets
Duplicados MD5 nos organizados             | 0 groups
Duplicados de nome na mesma pasta          | 0 groups
Nomes não canônicos em 01_READY             | 0
```

Report both operational meaning and counts. Rodolfo may ask whether UPLOAD_CANVAS files are "the same" as the vertical files; answer: they are source originals, while vertical files are cleaned derivatives, not binary duplicates.

## Safe sequence

1. Inventory the Drive fresh.
2. Separate layers:
   - RAW: paths under `MGS-AGENTS/CRIATIVOS/UPLOAD_CANVAS/`
   - staging/review: `MGS-AGENTS/CRIATIVOS/REVIEW/.../00_REVIEW` or `05_REJECTED`
   - organized: operation folders (`CC_*`, `JOBS_*`, etc.)
3. For `00_REVIEW`, review visually. Do not leave ambiguous items because of wording like "manual review" if a contact sheet/frame review can resolve them.
4. Apply decisions to the CLEANED review copy, not to the RAW source.
5. If using reports generated by copy-clean scripts:
   - `source_drive_id` normally points to RAW/UPLOAD_CANVAS.
   - `dest_drive_id` points to the cleaned copied file in organized/review folders.
   - Promote/delete/rename the `dest_drive_id` unless the explicit task is RAW cleanup.
6. If a RAW item is accidentally moved, restore it to its original UPLOAD_CANVAS parent from the fresh/previous inventory before reporting success.
7. Promote approved files from `01_READY_CANDIDATE` to `01_READY` by moving the same cleaned file; no additional metadata cleaning is needed if the copy-clean report already verified `clean=true`.
8. Delete or trash rejected review files only after Rodolfo explicitly approves deletion.
9. Re-scan Drive and validate the final state before reporting.

## Duplicate handling

- Inside organized folders, binary duplicate MD5 groups can be trashed after Rodolfo approves duplicate deletion.
- Keep one canonical file per MD5 group; prefer `01_READY`/`01_READY_CANDIDATE` over `REVIEW`, canonical names over raw names, and deterministic ordering.
- `UPLOAD_CANVAS` vs organized should not be judged solely by MD5 because cleaned derivatives differ at the binary level.

## Capability/delete pitfall

The Service Account may have `canEdit=true` but `canTrash=false`/`canDelete=false` when a file is outside the canonical Shared Drive. If Rodolfo approves deletion and capability is missing, stop and move the operation into an authorized Shared Drive context or correct the canonical membership/role. Never change identity. Report sanitized capability status only.

## Reporting language

When Rodolfo is trying to understand the state, explain in terms of layers and final state, not script internals:

```text
Pasta          | Função
---------------|--------------------------------------------------
UPLOAD_CANVAS  | RAW/original preservado
Pastas verticais| Cópias limpas, renomeadas e prontas
REVIEW         | Temporária; deve ficar zerada no final
```
