# Fleet browser checks after runtime maintenance

1. Build the target ledger from live app/pool/domain/root bindings, then separately label registered public sites outside the patched-host scope. A public smoke on another host does not certify its PHP packages. Include named test/backup roots without assuming their public availability is required; preserve unresolved purpose as a limitation rather than silently omitting them.
2. Pilot two different site classes before the full browser batch. Use existing trusted Playwright/Chromium without modifying a production dependency environment or another agent's protected browser profile. Use fresh contexts, bounded concurrency and no form submission, ad clicks, credential export or production mutation.
3. Append each completed target/viewport/route record immediately to JSONL. Require desktop and mobile home records for every target, plus one representative internal article when discoverable. Reconcile unique target IDs, counts, duplicates and omissions in code. Do not confuse repeated viewport visits with unique pages or sites.
4. Capture HTTP status, real final URL, visible body, applied stylesheets, page exceptions, first-party CSS/JS/image failures, failed visible images, page overflow and full-scroll coverage. Distinguish third-party ad/analytics failures, consent prompts, intentional carousels, site-wide common themes and default control/test homes from PHP or layout failures.
5. Scroll to activate lazy assets and retain full-page screenshots, but verify suspicious overlays/hero dimensions with a fixed viewport screenshot after a bounded settling interval. Contact sheets may aid triage, not replace exact-image inspection of suspected defects. Store large screenshot sets outside the auto-versioned repository and keep compact manifests/reports in the task's durable evidence.
6. For a seemingly stuck preloader, inspect document.readyState, pending requests, overlay pointer/opacity, delayed-script tags and body loaded classes. Test a harmless pointer movement in the browser before blaming PHP: delayed JavaScript may wait for the first interaction and release the loader only then. Report the proved delay/interaction coupling separately from the unproved historical cause; do not silently alter the loader configuration.
7. For a blank video hero, inspect video currentSrc, readyState, video dimensions, muted/autoplay/paused state and active slide geometry. A controlled browser-only play() can distinguish a loaded video from a missing file, but does not prove normal-user autoplay. Do not label it a missing image or server regression based on one headless screenshot.
8. For missing Elementor/builder chunks, first prove the current serving stack and actual installed files. Public legacy asset names do not prove the plugin is installed: a preserved static home may retain old builder JavaScript after the live theme/plugin changed. Compare bare, cache-busted and origin responses, serving rules/source timestamps and exact file existence before proposing cache clearing, a plugin install or a license change.
9. Never convert an HTTP200 fleet into an unqualified all-sites-green result. List named WAF/DNS exclusions and confirmed asset/content defects, distinguish current failure from proven regression, and state when no trustworthy pre-change visual baseline exists. The PHP patch predicate, visible rendering and absence of compromise are independent conclusions.
10. When the user requested inspection only, finish the whole read-only pass and present one repair boundary for the confirmed targets. Do not change themes, plugins, content, routing, cache or protected monetization merely to improve the audit score.
