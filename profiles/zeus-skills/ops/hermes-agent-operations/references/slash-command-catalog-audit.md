# Audit and edit an existing Hermes command catalog

Use when Rodolfo asks to update command-reference messages in an existing Discord thread. This authorizes editing Zeus's catalog, not executing its destructive commands or changing Hermes configuration.

1. Verify requester, thread and message authors. Fetch every existing catalog part; preserve original IDs and pagination. Save the originals and proposed payload in the profile scratch directory for rollback, never in another profile.
2. Read the `hermes-agent` skill and its slash-command reference. If skill_view says the skill is disabled, inspect those files directly without enabling the skill. Official reference: https://hermes-agent.nousresearch.com/docs/reference/slash-commands . A guessed `/user-guide/features/slash-commands` path can return 404: recover immediately through the official index `/docs/llms.txt` or the known reference, not repeated retries of the same missing page.
3. Resolve the deployed runtime from the real launcher and running gateway, then inspect `hermes_cli/commands.py` (`COMMAND_REGISTRY`). Do not equate the newest public docs with the installed build. Extract names, aliases, args, surface flags and config gates programmatically; compare them against every canonical catalog bullet. Count canonical names separately from aliases. Require exact set equality and uniqueness, not a prose total.
4. For changed behavior, inspect the actual handler and focused tests. Registry subcommands are autocomplete hints, not an exhaustive authorization or dispatch contract. Distinguish classic CLI, Ink TUI/Desktop, messaging gateway, platform-specific commands and config-gated commands. Inspect only relevant non-secret profile settings. A queued management operation may differ on a shared gateway queue versus a local CLI queue.
5. Validate native name/alias resolution and registry-owned executor bindings without invoking destructive handlers. If pytest is missing from the deployed runtime, do not install it merely to audit documentation: execute the dependency-free regression function directly using the runtime's module launcher. A verified launcher pattern is `hermes --run-module timeit -n 1 -r 1 "import runpy; runpy.run_path('/absolute/profile-scratch/smoke.py')"`. `hermes --run-module runpy /path/script.py` treats the path as a module name and is not a file-runner. Describe this validation as registration/resolution checks, not successful execution of every command.
6. Build bounded Discord payloads (each <=2000 UTF-16 code units), with all expected canonical names and aliases represented exactly once. Remove superseded change summaries. Mark missing local features accurately even if current docs advertise them. Preserve MGS gates for restart, update, credentials, billing, retention, deletion and autonomous background work.
7. If the exposed Discord tool lacks edit_message, use the established authenticated REST helper with the current profile's identity. Do not display or replace credentials. GET each exact message, require Zeus ownership and unchanged preimage (or already-desired content), PATCH only that target's content with allowed_mentions disabled, then GET the same ID and compare exact text. On 429, honor retry_after with a bounded retry; save per-message receipts so partial completion resumes only missing edits.
8. Report edited parts, additions/removals and meaningful syntax corrections concisely. A command removed from the reference is not necessarily an executed runtime change. Keep the existing thread title. No new catalog copies, attachments, configuration changes or gateway restarts are needed.
