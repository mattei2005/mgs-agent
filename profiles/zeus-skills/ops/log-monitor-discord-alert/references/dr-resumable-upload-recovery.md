# Encrypted DR upload recovery

- Reconcile the exact native job contract, supervisor lease, OS backup lock, slot journal and canonical-SA GET before retry. An HTTP 500 is a provider failure observation, not proof of its internal cause or of absent remote effects.
- For transient chunk errors and timeouts, query the same resumable session with an empty PUT and `Content-Range: bytes */TOTAL`. Resume only its acknowledged Range, reject offsets outside the sent bounds, and accept a completed metadata response without replaying data or creating another slot. Respect Retry-After; stop blind requests after five failed status probes or five no-progress attempts.
- Keep current recovery-point acceptance separate from historical snapshot recovery. If the legacy failure discarded its temporary ciphertext and its reserved native slot is still size zero, a corrective canonical quick backup can restore current protection but cannot recreate the lost historical instant. Preserve the empty slot and original error history; never label a later backup as the exact old snapshot.
- Run the canonical backup with `--no-retention` for scoped recovery; validate exact remote ID, placement, size, native MD5/SHA-256, canonical full-stream verification and native ACK GET. Do not rewrite scheduler last_status or launch another backup just because it still records the original failure.
- If the exact original encrypted backup has full native size/MD5/SHA-256 and the ACK already has its exact bytes but still carries `private_control_slot`, diagnose the ACK properties PATCH separately from upload. Invoke the canonical `mgs-offsite-backup.py finalize-direct --remote-id <original ID> --expected-name <original name>` under the unchanged job/owner gates. It checks the unique native slot journal, nonblocking backup lock, full corporate-SA stream and canonical same-ID ACK finalization, then records the recovered occurrence without replacing a newer success. Never generate another snapshot, rewrite scheduler history or claim the historical ciphertext was lost when the original bytes are present. The ACK publisher resumes metadata only after exact byte/binding readback; transient metadata failures reconcile GET before a bounded same-ID retry, while 429 and non-backup publication keep their prior gates.
- Distinguish an empty ACK slot from a lost backup: `CONTROL_SA_PUBLICATION_UNKNOWN` may leave the original ciphertext fully uploaded while its journal-bound ACK has size zero. Require fresh native size/MD5/SHA-256 and exact original IDs before using canonical `finalize-direct`; it can fill the same reserved ACK without creating another snapshot. If ACK bytes are already present, reconcile immutable content before metadata-only finalization. Never infer the provider's internal failure cause from the wrapper error alone.
- Persist the operation receipt and identify supervisor verification as pending when its native observer cannot yet recognize a direct canonical-run recovery. Existing owner/natural tick retains closure; a successful worker sentence does not certify it.
- Close a direct-run observer gap with a read-only, exact-occurrence adapter rather than another backup or scheduler-history rewrite. `scripts/mgs_dr_recovery_continuity.py` binds the approved hourly job/contract/last-run/slot to canonical PASS/no-retention receipts, fresh corporate-SA GET of backup metadata and native ACK, and GET of the existing REPORT-INFRA. Keep current protection restoration explicitly distinct from historical snapshot recreation; reject later slots, paused/claimed jobs, drift and missing evidence. Exercise the deployed `collect()` and an isolated queue closure; leave production completion and notice to the existing supervisor's next natural tick. ACKs reside in their canonical receipts folder, not the backup tier folder.
