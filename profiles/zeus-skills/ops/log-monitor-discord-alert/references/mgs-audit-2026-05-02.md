## Bugs Reais Mais Impactantes

### P0-3 — Webhook 1Password renomeado (silent fail 5 dias)
- `monitor-auto-push.sh` parado desde 27/04 sem alertar
- Causa: item 1P renomeado "MGS Alerts Channel" → "Alerts Infra Channel"
- Fix: atualizar nome + adicionar fail-fast loud

### P0-5 — Divisor Anthropic 88 vs 100 (14% inflado)
- API retorna centavos (USD × 100), divisor correto é 100
- DIVISOR=88 causava valores ~14% inflados há semanas
- Descoberto cruzando com CSV oficial Anthropic (não pela auditoria)
- **Lição:** cruzamento com fonte externa revela bugs que auditoria estática perde

### P1-11 — monitor-tool-loops.py (2 bugs em 1)
- `pass` silencioso: detectava erro mas não setava `is_error = True`
- `bare except:` engolia KeyboardInterrupt, MemoryError — anti-pattern Python

### P1-6 — Token parsing frágil (grep sem âncora + cut -f2)
- `grep "^DISCORD_BOT_TOKEN"` sem `=` pegava variáveis com prefixo igual
- `cut -d= -f2` cortava token se continha `=`
- Fix: `grep "^DISCORD_BOT_TOKEN=" | head -1 | cut -f2- | tr -d '"' | xargs`

## Falsos Positivos Notáveis (não patchar)

### `isinstance(sites, list)` — defesa intencional
- Parece dead code mas suporta 2 formatos de sites.json (dict OU list)

### `2>/dev/null || true` — supressão intencional vs bug real
- Contexto determina: `source .env` opcional = legítimo
- Diferente do P1-11 onde `pass` engolia erro funcional
- Regra: checar se o erro suprimido é esperado/opcional ou funcional

### `head -10 | grep "set -e"` — método errado de auditoria
- Scripts com headers documentais longos (15-27 linhas) tinham `set -e` fora do range
- Scripts mais bem documentados foram falsamente flagged
- **Método correto:** `grep -n "set -e" arquivo.sh` (no arquivo inteiro)
