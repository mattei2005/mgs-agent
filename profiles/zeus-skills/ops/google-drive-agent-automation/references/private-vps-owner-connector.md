# Private VPS owner archive authorization

Use only when Rodolfo explicitly approves a new isolated owner connector. Canonical authority and deployment state live in `/root/mgs-agent/context/drive-archive-owner-connector.md` and the initiative checkpoint, not in this procedure. Approval of an architecture is not a live credential or production cutover.

## Boundaries

- Agents remain on `mgs_google_workspace_auth.py` and the canonical SA. Do not change selectors, restore retired OAuth files or use owner tokens as a Google-agent fallback. Keep owner client/secret/refresh token in one new 1Password item; persist no plaintext secret in code, config, logs, process arguments, chat or evidence.
- General Google Drive user OAuth clients are created through Google Auth Platform. Do not substitute IAM workforce OAuth clients (their scopes do not include Drive) or IAP clients (locked to IAP redirect behavior). An automated Google browser rejection before the password is a browser-security gate, not a wrong password; stop and use the owner's normal browser for setup and consent. Do not relay passwords merely because a Login item exists.
- Use a private HTTPS callback. Tailscale Serve and Funnel are different: only Serve is allowed by this design. Preserve other listeners/routes. A node advertising HTTPS capability does not prove Serve is enabled; reconcile `tailscale serve status --json` after a timeout. When the CLI provides the legitimate enable link, record pending admin activation rather than claiming the callback URL is reachable. A foreground Serve process can remain the silent, tracked reverse-proxy service while awaiting that activation.

## Current authorization component

- `python3 scripts/mgs_archive_owner_auth.py init` creates/adopts one uniquely named empty API Credential item, validates native item/vault IDs and approval binding, and writes only a public config. Read back field-presence booleans; blank client fields mean setup is still pending.
- `python3 scripts/mgs_archive_owner_auth.py status` reports booleans only.
- `python3 scripts/mgs_archive_owner_auth.py serve` binds only loopback. The private setup page links the actual Cloud project and explains Web client creation, exact redirect URI and protected 1Password entry. It generates a real Google consent URL only after an actual client ID/secret exist; never invent a client or authorization code to make a link look ready.
- Require exact origin and a fresh CSRF cookie/form pair, ten-minute single-use transaction state, PKCE S256, exact Drive scope and offline consent. Consume state before exchange. Test wrong origin/state, expiration, replay, wrong Google account/native permission ID/root, missing refresh, extra scopes and a client changed during consent.
- Verify a real refresh grant, authenticated native owner and exact archive-root ownership/capability before storing refresh. Re-read the vault item and require the client tuple/approval to remain unchanged before save; compare secret readback only in memory. Store a credential-safe authorization proof and audit event; leave REPORT-INFRA pending for the next foreground reconciler. Never enable production merely because authorization succeeded.
- Before asking an operator to enable HTTPS again, bind the admin panel's exact tailnet DNS suffix to native `CurrentTailnet.MagicDNSSuffix`, the node `DNSName` and relevant peer names. A green Serve wizard for a node ID does not prove the subsequent DNS panel is on that node's tailnet. If suffixes differ, switch the admin console to the existing corporate tailnet/owner identity; do not rename a tailnet, change the pinned OAuth origin/redirect, or migrate nodes to match the unrelated screenshot. Keep Tailscale admin identity separate from Google Drive owner consent.
- A green `Tailscale Serve is ready to use` browser page is not endpoint proof. Confirm the exact requested node ID, `serve status`, listener and native `DNS.CertDomains`. If HTTPS is not yet provisioned, inspect the correct tailnet's Admin DNS → HTTPS Certificates gate; do not switch to HTTP/Funnel, restart Tailscale or change shared DNS to hide the issue. Native `DNS.CertDomains` and actual CA/hostname-validated TLS plus HTTP readback are acceptance evidence. Do not require a particular HTTPS key in `status.Self.CapMap`: it can remain absent even after Serve succeeds and native TLS returns HTTP 200. For diagnostic capability checks, compare explicit keys rather than searching all capability URLs for the substring `https`. The first connection may time out while the managed certificate is being provisioned: perform a bounded longer TLS probe and verify the real route before escalating or requesting another operator click. A host with `accept-dns=false` may not resolve its own MagicDNS name: test TLS with the tailnet IP plus correct hostname/SNI without changing system resolver settings. Keep this separate from an actual absent listener/refused connection.
- The HTTP service must suppress request logs, because OAuth callback URLs contain codes. Use no-store/referrer/CSP headers. Unknown Host, unconfigured client and malformed transaction fail closed. Bootstrap endpoints never copy, move or delete media.
