- Read `docs/mgs-router-campaign-clicks-equal-distribution.md` and receipt `data/mgs-router-campaign-features-validation.json` before resumption. Approved scope is aggregate GET/302 counts, inclusive calendar periods in America/New_York, same-menu return and equal probabilities. Previous no-clicks scope is historical; do not reintroduce it as an active prohibition. Conversion/user tracking and postbacks remain out of scope.
- Equal split uses identical decimal relative weights (100/N rounded to12 decimal places), never distribute integer-percent remainder across23 destinations: that changes their probability. Validate imported integral weights as before; Target.Weight is float64, with finite positive bounded validation and tolerance only on fixed percent sums. Keep random draws below total via Nextafter. Source URLs/order/catalog identities/query contracts stay untouched.
- Treat the equal button as draft only; only Save applies. Public QA previews20/23 and cancels without POST. Persist/save/reload tests belong in isolated local state, not live campaigns.
- Clicking the already-active Campaigns menu must hide the editor and return to list; changing only hash or view cannot do this because the hash is unchanged. Preserve filters/pagination and discard unsaved changes only. Apply the same behavior to Landing Pages.
- Click identity is public host+path, not editable name/group or destination. Count successful redirect GETs once; repeated requests, bots and link previews are included. HEAD, errors/disabled/unknown routes and rejected methods do not count. Do not imply human-only or unique clicks.
- Storage is private SQLite daily aggregates: clicks.sqlite with WAL/FULL, bounded wait and atomic UPSERT. Never collect visitor identifiers or queries. API requires authenticated admin host; no clear/delete endpoint. Same path reused shares history; cloned new path starts without events. Collection since is persistent; older periods are not reconstructed.
- Validate production routes using HEAD variants after adding click accounting; broad GET sweeps and direct sampling now modify totals. A single canary GET is permissible to prove requested recording, must remain honestly counted and disclosed. Do not delete or suppress it merely to make the dashboard look clean. If a full GET sweep is necessary, obtain/record its scope and disclose QA clicks.
- Keep --check and provisioning paths from opening/creating click stores. Validate actual service restart preserves since/counters; tests on newApp alone do not prove systemd durability.
- Back up SQLite using online backup API and integrity_check; a bare main-file copy misses live WAL data. Preserve click store even on binary rollback. Never restore old code blindly after concurrent fractional saves: reconcile protected config before rollback; old integer code rejects fractions.
- A write failure must preserve redirects, expose sanitized failure counter and degraded health, and show an honest warning. API failure renders emdash rather than fake zero. Do not retry an ambiguous UPSERT and double-count.
