# Auditoria read-only de versões WordPress no portfólio

- Derive o conjunto autorizado de `context/sites.md` e `data/mgs-domain-scope.json`; reconcilie cobertura por hostname único em código. Não use totais ou PHP do inventário histórico como estado atual.
- Consulte RunCloud com o User-Agent canônico e paginação completa. Se receber 429, respeite Retry-After/cooldown; evite fan-out de consultas por domínio. Use o transporte SSH já autorizado para o diagnóstico, sem mudar credenciais ou permissões. Falha da API não prova falha dos sites.
- Em SSH, valide `wp-config.php`, owner, `home`, core, plugins e temas por instalação. `wp eval --skip-plugins --skip-themes` pode ler plugins e os transients de atualização; verificações `wp_update_plugins/wp_update_themes` podem manter cache recente e não carregar updaters comerciais. Preserve timestamps e não prometa cobertura integral de plugins premium/customizados.
- Quando um path histórico não existir, não classifique o domínio como desligado. Teste REST público com User-Agent explícito, decodifique JSON e confira `namespaces`; busca textual por `wp/v2` falha com barras JSON escapadas. Um 403 ao User-Agent padrão pode desaparecer no transporte MGS já aceito.
- Recupere a referência administrativa canônica no 1Password via `mgs-op-with-service-account.sh`. Use GET autenticado de `/wp-json/wp/v2/plugins?context=edit&per_page=100` e `/wp-json/wp/v2/themes?context=edit&per_page=100`; valide paginação quando presente. Nunca imprima segredo, Authorization ou payload bruto da credencial.
- Compare versões instaladas com os endpoints oficiais WordPress `plugins/update-check/1.1/` e `themes/update-check/1.1/`. Normalize o identificador REST adicionando `.php` ao basename do plugin somente para a consulta oficial. Use versões numéricas em código, não comparação lexicográfica. Mantenha updates comerciais identificados pelo próprio WordPress separados dos não verificáveis.
- Para PHP HTTP, associe o título exato `php-fpm: pool <webapp>` ao executável em `/proc/<pid>/exe`. Versão do CLI ou PHP histórico da API não comprova runtime web; ausência de worker deixa a verificação pendente.
- Salve lotes e resumo credential-free no scratch e valide `allowed - covered`, `covered - allowed`, unicidade e totais antes da resposta. Conte separadamente sites, plugins instalados com update e temas com update; inclua inativos, identificando essa decisão.
- Reporte lista por domínio, escopo, fontes e limitações. Diagnóstico não autoriza instalar, atualizar ou remover componentes; mudanças de produção exigem o gate aplicável.
