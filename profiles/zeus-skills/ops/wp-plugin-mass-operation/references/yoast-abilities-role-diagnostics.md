# Yoast Abilities: role and transport diagnostics

Use for a scoped Yoast permission incident, not as authorization to promote users or persist scores.

1. Confirm the exact domain, WordPress user ID/login and live roles through authenticated `GET /wp-json/wp/v2/users/me?context=edit`. Require Rodolfo's explicit authority before a role change; preserve passwords, email and application-password records. Snapshot capabilities, validate the exact installation with `home`/`siteurl`, promote only the approved identity, then independently read back through REST and WP-CLI. Keep non-secret role metadata in the existing 1Password item aligned; never rotate a secret implicitly.
2. Read the installed ability contract before executing it. Yoast score retrieval can require `wpseo_manage_options`; Editor may be able to publish and edit advanced metadata while still receiving `403 rest_ability_cannot_execute`. Advertisement in the schema does not prove permission to execute.
3. For WordPress Abilities GET `/wp-json/wp-abilities/v1/abilities/yoast-seo/get-seo-scores/run` and `/get-readability-scores/run`, supply structured **query** input, e.g. requests `params={'input[number_of_posts]': 11}`. GET JSON bodies are ignored by the native controller's `get_input_from_request`; no query input yields `400 ability_invalid_input`. Inspect the live schema and preserve declared integer/range constraints.
4. Treat those two abilities as retrieval of existing scores, not calculation or persistence. They may return published older posts and omit new drafts; do not use a returned count as proof the requested new IDs were analyzed. Verify every approved ID's postmeta and corresponding `yoast_indexable` row independently.
5. Becoming Administrator does not expose unregistered score metas in REST. Reinspect `OPTIONS /wp-json/wp/v2/posts`; if only input fields are registered, do not assume that writing hidden fields succeeded. Prefer an already-authorized native editor or a verified WP-CLI per-post path; changes to plugin/MU/locale need their own scope.
6. If historical webroot is missing, discover matching application directories read-only on the already-identified host and validate `home` before acting. A guessed old directory and an API transport error do not prove that the installation is absent. Use the canonical RunCloud User-Agent; if API rate-limits persist, use already-authorized pinned SSH rather than repeated blind calls.
7. Keep diagnostic scope separate from publication: preserve exact new-ID manifest, content hashes and statuses; report successful permission recovery separately from uncomputed/unpersisted scores. Site/user `pt_BR` is not proof of correct Spanish analysis; verify the actual per-post analysis context without silently changing the global locale.
