# Static Chat Wrapper Diagnostics

Use this reference when Rodolfo asks whether a chat/quiz page is loading an unexpected JBF/digital-trust wrapper variant such as `_facebook_br.builder.js` instead of `_direct_br.builder.js`.

## Goal

Determine whether the suspicious wrapper suffix is present in:

- the live rendered HTML;
- the canonical plugin/config files;
- WordPress head/footer/snippet layers;
- CDN wrapper variants;
- cache or request-context-dependent output.

Do this read-only unless Rodolfo explicitly asks to change configuration.

## Read-only diagnostic sequence

1. Fetch the public route HTML with a normal browser-like user agent.
   - Check `window.wrapper_url`, `window.utm_source`, `window.company`, and `window.domain`.
   - Count exact tokens: `_facebook_br`, `facebook_br`, `_direct_br`, `wrapper_url`, and the expected wrapper basename.

2. Repeat with likely context variations.
   - trailing slash and no trailing slash;
   - `?utm_source=facebook`;
   - `?fbclid=TEST`;
   - `Cache-Control: no-cache`;
   - if origin IP is known, curl with `--resolve domain:443:ORIGIN_IP` to bypass Cloudflare edge cache.

3. Probe CDN variants explicitly.
   - Example pattern: `https://assets.jbfdigital.com.br/assets/{company}/{domain}/{company}_{domain}_{source}_{country}.builder.js`.
   - A `200` for a suspicious suffix only proves the variant exists on CDN; it does not prove the live page is currently selecting it.

4. Inspect accessible site code/configs.
   - Prefer SFTP read-only download of the relevant plugin/theme directories.
   - Search plugin config JSON, templates, theme, and head/footer/snippet plugins for the same tokens.
   - For `mgs-chat-funnels`, the wrapper URL may be generated by `ad_wrapper_url()` from `ad_company` and `ad_domain`; if live HTML has an extra suffix not generated by the plugin files, suspect a separate head/snippet layer or cached/older output.

5. Separate confirmed facts from hypotheses.
   - Confirmed: exact live `window.wrapper_url` and whether the suspicious token appears in current HTML/code.
   - Hypothesis: request context, referrer, cookie/localStorage, Cloudflare/APO cache, or DB-stored snippets may have selected an alternate wrapper.

## Reporting pattern

Keep the answer short and operational:

- state whether the suspicious suffix appears in current live HTML;
- state the current wrapper URL observed;
- state whether code/config search found the token;
- if the CDN variant exists, say it exists but is not proof of live selection;
- call out any unresolved layer, especially DB snippets/admin settings that were not readable from files.

## Pitfalls

- Do not infer infection or compromise just because a CDN variant returns `200`.
- Do not claim the site never serves a suffix if you only checked one request context.
- Do not mutate WordPress/plugin config during a “confere” request.
- Do not expose credentials or raw 1Password values while checking SFTP/WordPress access.
