## Runtime Caveats

- **Persistent SB automation runtime:** production SB/DTR scripts must use the persistent Python/Playwright environment at `/root/.local/share/mgs/sb-venv` and the authenticated storage state at `/root/.local/share/mgs/smartbidding_state_headed.json` (mode `0600`). Never place either runtime dependency under `/tmp`: reboot/tmp cleanup removes them and causes cron exit `127` or missing-state failures. After rebuilding or migrating, validate imports, a local Playwright Chromium launch, a real read-only SB capture, and the affected Hermes cron by job run/readback. Audit the complete transitive execution chain—not only the cron wrapper—including imported helpers under `/root/mgs-agent/work/`; a durable wrapper can still fail if an imported module retains `/tmp/sb-venv` or `/tmp/smartbidding_state_headed.json`.
- **SB session-expiry validation pattern:** a storage-state file can exist with mode `0600` and still be expired. Before blaming a consumer refactor, probe the live `/company` response and authorization capture. Treat HTTP `401` or a missing captured authorization header as an authentication-state problem. Refresh through the canonical headed/Xvfb login with the existing 1Password credential—do not reset or alter the credential. Save the replacement storage state **only after** a live `/company` probe returns HTTP 200, then enforce mode `0600`; a dashboard page render alone is not the save gate. Recovery sequence is: login-only refresh → `/company` 200 → bounded exact-consumer dry-run → requested apply run → external Sheet/state readback. Completion requires consumer-level evidence after refresh—not only a successful dashboard login: exit `0`, expected publisher/row counts, zero errors, and readback of every affected external report/cron state. If the consumer also depends on Google OAuth/Sheets, validate and recover that dependency separately before the final apply; one healthy auth path does not prove the other. API parsers should fail clearly on non-200 or wrong JSON shape before iterating rows, rather than surfacing a misleading `AttributeError`.
