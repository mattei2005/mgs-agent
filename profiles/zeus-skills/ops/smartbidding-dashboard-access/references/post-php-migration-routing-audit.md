# Post-PHP migration — full Smart Routing audit

Use after the owner reports a fleet PHP migration and asks to test every routing entry. This is a read-only audit, not authority to republish drafts, rewrite routing, alter cache/plugin settings or retire pools.

1. Recover the owner's original request and live target bindings. Enumerate all RunCloud API pages and both MGS SB companies. Project fields before persistence/output: `/company` contains nested VPS/WordPress credentials and Discord tokens, including unrelated companies. Never print or save its raw body, even a truncated sample. Allowlist companyId plus publisherId/name/url/active, then discard the original object.
2. Use the durable Zeus state `/root/.local/share/mgs/smartbidding_state_headed.json` and interpreter `/root/.local/share/mgs/sb-venv/bin/python`, headed/Xvfb, session lease and browser resource budget. Legacy `/tmp` paths are discovery hints, not the durable source.
3. Freeze all pools via the read-only `POST /routing` query and parse every ROUTES array. Count configured rows, unique route identifiers, distinct executable links and distinct destinations separately; duplicate identifiers with different UTM_Content are not one test case.
4. Resolve each routing hostname from the publisher's actual deployment. Openzed/Cliquet use `sr` for primary and `srf` for Finanzas; other publishers may route on the main site. Preserve literal empty configuration values. Derive a valid medium matching the pool's pattern; do not replace an empty UTM_Content with fabricated content.
5. Test every distinct route with redirect following disabled and explicit audit parameters, then every distinct landing path through its complete redirect chain. A preserving first 302 does not prove final retention: WordPress old-slug 301s can strip the query. Record X-Redirect-By, final URL and exact parameter/value equality. Test the canonical target directly to localize that loss.
6. Retest failures with original query, bare/slash variants and current API state. Keep initial evidence and latest verified state separate; report recovered transient failures separately from persistent defects. Do not blame PHP from a 404 alone.
7. Join every failed destination to its referring route entries. Read WordPress post status and `_wp_old_slug` using SELECT only. Distinguish draft content, missing route aliases, published canonical targets, ambiguous old-slug matches and sites outside the migrated fleet. Never republish a draft just to make the audit green. SB `healthy=true` is metadata, not proof of HTTP health.
8. Validate live configured PHP, FPM executable, uncached origin and PHP-8.3 WordPress bootstrap independently. Compare only appended bytes of exact current log paths; old rotated logs and substring-matched sibling app logs are not new migration errors.
9. Render desktop/mobile under a bounded browser lease. Wait for loader/animation readiness and re-open blank-looking cases after settling before calling them blank. Keep Cloudflare challenges, unpublished/empty homepages and nonexistent backup DNS distinct from PHP crashes. Without a trusted before image, label visual regressions unproved.
10. Preserve machine-readable evidence and totals in a durable report, update the checkpoint, inventory/audit/report the local governance changes, and state the exact production-write gate. Transport large remote Python through SSH stdin, not argv: embedded evidence can exceed ARG_MAX even though the code is valid.
