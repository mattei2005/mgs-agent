## Decision

## Credential selection

Two 1Password items now share the exact title `BOT B012 Token`: the former reserve item and the current B012 item created from the B011 template. Title-based resolution selected the retired reserve item and is unsafe.

Production requirements:

- Pin the current validated B012 item by immutable 1Password item ID in `b012-dtr-link-watch.sh`.
- `mgs-op-item-resolver.py` must omit duplicate exact titles from title resolution and expose them as `duplicate_titles`; callers must use an explicit immutable ID.
- Never print `app_id`, `access_token`, `app_secret`, page tokens or DTR credentials.
- The duplicate reserve item remains non-operational until Rodolfo explicitly authorizes credential cleanup/deletion.

The current item was validated without exposing secrets: app metadata HTTP 200 with ID match, user token `/me` HTTP 200, `debug_token` HTTP 200 with `is_valid=true` and app-ID match, and `/me/accounts` HTTP 200.

## Cutover finding

This proves the new app credential is healthy but the per-profile DTR OAuth connections still point away from B012 and require reconnection. Do not describe B012 as operationally migrated until those links validate.

The retired B011 cron run at 14:24 ET evaluated the now-retired app and wrote false X markers during the transition. The B011 cron was paused before cutover; the 15:04 generic Meta `/roles` run was interrupted and B012 was added to its DTR-only exclusion guard.
