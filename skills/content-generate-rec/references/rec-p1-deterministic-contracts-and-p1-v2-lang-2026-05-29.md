# REC/P1 deterministic contracts and P1-v2 language lesson — 2026-05-29

## Context

During the REC+P1 universal-contract refactor, a patch introduced `contracts/cc-rec.md` and `contracts/cc-p1.md` plus `--lang`, but review exposed a critical assumption error: neither REC nor P1 article generation was LLM-based at runtime.

## Durable lessons

- `cc-rec.md` and `cc-p1.md` are versioned editorial specs for deterministic Python generation, not runtime LLM prompts.
- `load_rec_template_contract()` validates/telemeters the REC spec and prefers `cc-rec.md`, but article prose still comes from deterministic Python (`generate_article_local`, `rec_top_of_page_copy`).
- P1 historically generated HTML via deterministic Python (`generate_p1_body`). Removing the `template_key == 'gb-cc-en'` gate only unlocks sites; it does not make P1 obey `cc-p1.md` as a prompt.
- Do not introduce LLM/runtime providers, Lovable AI Gateway, Anthropic/Claude, OpenAI API, or pay-per-token article generation unless Rodolfo explicitly approves that architectural change.

## P1-v2 acceptance contract

For deterministic P1 multi-language support:

- Supported first-release languages: `en`, `es`, `pt`, `tr`.
- Unsupported language must abort explicitly before publish.
- `--lang` must drive visible deterministic output: title, excerpt/subtitle, meta-description, headings, body scaffolding, LazyBlock labels/tags/CTA/redirect text where generated by the runner.
- JSON must expose:
  - `policy.contract_p1`
  - `policy.contract_mode = deterministic_python_from_versioned_spec`
  - `policy.effective_language`
  - `policy.llm_runtime = disabled`
- Existing WP pipeline must remain intact: REC fetch, official source gates, card/featured image, Yoast, taxonomy, create/update, public verification.

## Validation pattern

Use three layers:

1. `python3 -m py_compile scripts/mgs-rec-runner.py scripts/mgs-p1-runner.py scripts/mgs-rec-p1-orchestrator.py`
2. Static grep/review to ensure no new runtime LLM/provider/API-key path was added.
3. If full orchestrator dry-run is blocked by official URL preflight before P1, validate P1 generation directly by importing `mgs-p1-runner.py` and calling `generate_p1_body()` / `title_and_meta()` for `en`, `es`, `pt`, `tr` with fixture card facts. Report clearly that this is unit-level P1 validation, not full REC+P1 orchestration.

## Pitfall

Do not claim “runner reads the contract” as if the markdown controls prose at runtime. Say: “runner validates/telemeters the versioned spec; deterministic Python remains the article engine.”
